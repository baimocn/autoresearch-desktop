# dsh-model-council —— 模型议会

一个**独立**的工作台面板：让多个模型按固定身份**对抗审议**一个方向，
最后由裁决者定夺。与 AutoResearch 工作台不共用面板、不共用路由、不共用配置。

## 为什么不是「多模型讨论」

让几个模型各写一版再取共识，分歧会被**平均掉**而不是被**解决**。三个模型
若共享同一批训练偏差，它们会一起错，而且「多数一致」会让这个错误显得更
可信 —— 风险反而**升高**。所以这里给每个身份固定且互不重复的举证义务：

| 身份 | 举证义务 | 明确禁止 |
|---|---|---|
| **议员** councilor | 给出一个明确主张：判断、依据、预期收益，以及最可能失败的地方 | 不许罗列多个方案让裁决者挑 |
| **对抗者** adversary | 必须找出 ≥3 个具体失败模式 / 反例 / 未验证假设，逐条编号 | 找不到就写「我找不到」；不得编造凑数 |
| **裁决者** adjudicator | 通读全部发言后裁定：结论 / 理由 / 执行条件与不可逆性 / **推翻条件** | 不得取多数意见，不得和稀泥 |

产出不是「一个更对的答案」，而是「一个方案 + 已知的反驳 + 明确的代价 +
一个能被推翻的裁定」。**裁决者恰好 1 位，对抗者至少 1 位** —— 缺对抗者的
议会只是并行自说自话，暴露不了偏差。

## 每路独立配置

每位成员独立设置 **地址（baseURL）/ 协议 / 模型 / 密钥**，不引用全局 provider
表。模型 id 不靠手打：点「探测」拉取该端点的模型列表再选。

支持的协议（与 pi-ai 一致）：`openai-completions` / `openai-responses` /
`anthropic-messages`。baseURL 是否带 `/v1` 不统一，所以每个协议按候选路径
顺序试到第一个非 404，不需要用户纠结。

密钥写进 `$DSH_HOME/.credentials.yaml` 的 refs 段（引用名
`COUNCIL_<ID>_API_KEY`），**议会配置文件里只有引用名**；页面只显示
「有值 / 无值」，不回显密钥本体。

## 议事流程

1. **配置**：议事厅左侧「议会配置」页配好成员，保存。
2. **新建会话**：填议题。
3. **开一轮**：议员依次陈述（后发言者看得到先发言者），对抗者依次攻击。
4. **请裁决者裁定**：裁决者通读议事记录后给出裁定（含推翻条件）。
5. 主持人可随时在对话框插入发言，影响后续发言者；可反复开轮与重裁。

## 接入正在跑的普通会话

```
/council          建议式：注入纪律 + 提供工具
/council-strict   强制式：高风险工具须先取得裁定；询问用户被重定向到议会
/council-off      退出
```

开启后系统提示多一段 `<model_council>` 纪律：当对话走到需要人工决策的点
（在方案间选择、不可逆动作前取舍、本来要问用户），**不要停下来等用户** ——
调用 `council_convene`，把「本轮上下文 + 候选选项」交给议会，把返回的 `chosen`
当作用户的选择继续执行。这就是无人监管模式。

两个工具（模式未开时直接拒绝，并告诉调用方该执行哪条命令）：

| 工具 | 作用 |
|---|---|
| `council_convene` | 召开议会 `{question, context, options?, rounds?, waitMs?}`；超时返回 `running`，用 `council_read` 续等 |
| `council_read` | 读取一场议会：状态 / 当前发言人 / 完整议事记录 / 裁定 |

强制式拦 `bash` / `pwsh` / `write` / `edit` / `str_replace_editor`（判据是不可逆，
只读工具一律不拦）；`ask_user_question` 由 guard 重定向到议会而不是简单拒绝。
拿到裁定后高风险工具自动放行。

**刻意不接门禁**：议会不参与 `advance`，是决策辅助 —— 替你做选择，不为结果背书。

## 文件

```
$DSH_HOME/model-council.json              参与者名单
$DSH_HOME/.credentials.yaml               各路的密钥（refs 段）
$DSH_HOME/model-council-sessions/<id>.json 会话与完整议事记录
```

## 长任务与失败处理

一轮议事 = 成员数 × 单次模型延迟，所以「开一轮」只负责**启动**，页面轮询
进度；进程重启后历史仍在，但不会假装那次运行还在继续。某一路鉴权失败或
超时，会在议事记录里留一条明确的错误条目 —— 不静默跳过，否则裁决者会
基于残缺信息定夺。

## 模块

| 文件 | 职责 |
|---|---|
| `lib/roles.js` | 三身份定义、举证义务、提示词构造 |
| `lib/protocols.js` | 三协议直连：拉模型列表 + 一轮对话 |
| `lib/config.js` | 配置读写、结构校验、密钥分层 |
| `lib/engine.js` | 会话、逐位发言、裁定、落盘 |
| `index.js` | 宿主路由（配置 / 探测 / 会话 / 发言 / 开轮 / 裁定） |
| `client.js` | 浏览器面板（议事厅 + 议会配置） |
