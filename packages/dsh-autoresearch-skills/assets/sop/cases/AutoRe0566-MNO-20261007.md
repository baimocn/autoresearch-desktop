## 三、根因（三层，按重要性）

1. **论文提供的可复现信息不足**（外部因素，但应在选题阶段识别）
   - 正文未给出 Re=5000 的完整训练配置；官方仓只有 Re=500 的脚本
   - README 的关键参数表述有歧义（"内半径的下界应为 norm×S"）
   - **官方脚本的默认值在 Re=500 下都不能让 Reference 优于 Baseline**（这是最硬的证据：方法与配置的匹配依赖论文未公开的信息）

2. **我的选题判断失误**（主因，应该在 P0/P1 阶段拦住）
   - **没有做"增益探针 + 判定预解"**就投入完整协议 → 应在 3–4 小时内发现不可行，实际花了 26 小时
   - **指标未直译论文主张**：论文讲"耗散性/稳定性"，我测"统计精度"
   - **参数跨规模未做数值反推**：官方 Re=500 用 10000（比数据 min_norm 13786 还小 0.73 倍），我却按文档字面为 Re=5000 算了 86204

3. **调度工程问题**（浪费但非主因）
   - 评分环节串行、依赖轮询 → 训练完成后卡空转（估计浪费 ~15 卡时 ≈ 25 元）
   - 3 次脚本语法错（中文引号/CRLF）导致任务未启动
   - `backfill.sh` 与手动指令打架

## 六、10 条已修复的生产 bug（与数据集无关，全部有前后对照）

1. `artifacts` 落入 `[task]` 表（SOP §5.4 预警）→ 移顶层
2. `make_reward.py` 对 `B_mean=null` 崩溃 → ERROR 通道
3. Dockerfile `chmod a-w` 对 root 无效 → `USER appuser`
4. Starter 预裁剪数据切片错位 → 相对帧对齐
5. `train_saved` 按 `*.pt` 判断，而官方 checkpoint **无扩展名** → 改用 `Weights saved`
6. `check_model_def` 裸子串扫描误伤 docstring 里的 "subprocess" → 纯 AST 检查
7. 编排器在模型未生成时评分 → 加"训练完成才评"门 + 自适应重试
8. `convert_official_ckpt.py` 硬编码 `domain_size=64` → `--domain-size` + 前向尺寸校验
9. Windows 生成脚本 CRLF 导致 bash 解析失败 → LF + `sed -i 's/\r$//'`
10. SSH 重试导致多实例并发 → 全局 flock + `/proc/*/cwd` 检测
