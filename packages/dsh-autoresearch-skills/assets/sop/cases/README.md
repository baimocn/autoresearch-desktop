## 案例 1：auto1851 PSQN — baseline 口径不可比（最经典）

**事实**：walker2d-medium-replay，seed41，1e6 步。vanilla（本方基线）末点 **82.94**，PSQN（论文方法）末点 **80.10**。

**三种口径的 Δ 全部 ≈0 或负**：

| 口径 | Δ |
|---|---|
| 末点（官方 verifier 口径） | **−2.83**（负） |
| best-checkpoint | +1.08 |
| 稳态均值（配对 t=0.33, n=18） | +1.71（与 0 无显著差异） |

**论文声称 Δ = +34.0，实测差 6.3 倍。**

**根因链**：
1. 论文左侧 baseline 58.0±3.6 是**「原文献报告值」**（论文未自跑）
2. 社区公认值 **81.8**，本方实测 vanilla **82.94**（比公认值还高 +1.14 ⇒ 实现正确，非 bug）
3. ⇒ **+34 的增益空间建立在一个被低估 23.8 分的 baseline 上**
4. σ=1.6 是从 58.0 那个 baseline 上测的 ⇒ **方差与均值不同源**
5. 组内 sd=17.36 ⇒ `σ_B ≳ 17.36/√20 ≈ 3.88` ⇒ **3σ_B 下界 ≈ 23.3 > Δ 上界 +1.71** ⇒ **补 seed 数学上不可能过线**

**本可拦截**：`tools/paper_screen.py --community-baseline 81.8 --reported-baseline 58.0 --delta-percent 34`
→ 当场输出「扣除 baseline 低估后增益 **−4.1** → 该题不可做」（已实测，退出码 1）

**已烧**：≈3.7 GPU·h

## 案例 2：auto1430 MemCast — trivial 基线反超

**事实**：**persistence（2.40）打败论文方法（2.69）与基线（6.36）**。
**判据数学不成立**：最笨的方法（复制上一帧）最好，说明指标不测量论文声称的能力。
**本可拦截**：跑 1 次 persistence 基线（分钟级）

## 案例 3：auto1352 Meta-rater — 判据被混淆变量污染

**事实**：两侧数据不可比——**长度差 8.7 倍**、md5 与单维锚点逐字节相同、`dsir` 维与长度 `rho ≈ −0.96`；reference 的"最优权重"出自**恒输出常数模型**（=随机挑）。
**本可拦截**：对比前必查六项（大小/行数/长度分布/source/id 重叠/md5）

## 案例 4：auto1633 VSD — 剂量-响应单调恶化

**事实**：1ep → 5ep 的增益**单调恶化**（1ep −0.255 → 5ep −0.461）；官方权重校准 τ=6.33 已排除管线问题。
**教训**：多个档位全为负 ⇒ 不是调参问题，是**方法不成立**；应停手而非继续加档。

## 案例 5：auto0565/0566 — 论文可复现信息不足

**0565 AL4PDE**：不确定性选点 **6 个配置全部劣于随机**；若坚持原协议需 **240 GPU-h**。
**0566 MNO**（本仓库主案例）：五个方向系统性证伪；官方未公开 Re=5000 配置；**实花 530 元，其中 ~480 元本可被 L1/L2 拦住**。详见 `cases/AutoRe0566-*.md`

## 案例 6：auto2001 MedMamba — 并发与交付组装

**成功交付**，但制作期密集事故：
- **三会话并发互写权重**（token 烧三倍，部分 5444 万 tokens 为三重迭代浪费；权重实测漂移 0.9132 ≠ 声称 0.9586）
- data_loader 标签错位 2 位
- 多包一层壳、NOP 缺失、task.toml 顶层键错置
**教训**：`flock` 单实例锁 + 交付物单源生成

## 案例 7：auto2768 DREAM — val 泄漏（进行中）

**事实**：r28 起用**干净 val 标签**当训练种子 → r31 分数跳到 **99.9**（泄漏的典型特征）。
**教训**：泄漏检查应进 smoke（分数突然跳高 = 红旗）；Hidden 缺失 fail-closed。

## 案例 8：auto0340 IQ-MPC — 时限与状态失真

**事实**：三轮合计 **0.81h**（官方要求 **10h**，差 12 倍）；领题表**从未登记**、优化面 zip **未生成**（记忆误记"已交"）。
**教训**：时间账乘失败系数并实时汇报；"备好 ≠ 已交"

## 案例 9：work_EMERALD — 无结论（流程漏洞）

**事实**：只剩 `scripts/`，**无 README / 状态 / 结论 / 交接** → 死因完全无记录。
**教训**：**未收录 = 未吸收**。每题（含失败）必须留一行结论。
