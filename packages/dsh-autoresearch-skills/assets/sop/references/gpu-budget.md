# GPU 选型、租期与预算

本页用于 AutoResearch 出题的资源规划与审批材料，不提供实时价格，不租资源，不联网，也不修改任何配置。金额由调用者提供；不得用示例数字冒充市场报价。

## 官方口径

- 项目优先使用 H20 或 L20；通用资源边界为 CPU 不超过 64C、单个 Job 默认不超过 8 张 GPU，按具体任务卡与审批要求复核。16 CPU、64GB、1 张 H20 等配置只是示例。
- 作业表填写 GPU、CPU、内存规格、数量、天数、训练总成本，按“规格单价 × 数量 × 天数”报小组长审批，审批通过后再使用。
- 已查阅的项目资料没有统一的“GPU 型号—租价—固定天数”表。价格取自实际供应商报价并记录来源、日期、计费单位；天数取决于任务预跑和完整制作计划。
- 两组 Agent 分别至少有效迭代 10h，建议每组安排 10.5–11h。只有满足全部例外条件并提供证据时，才能各至少 7h。两组时长不能相加达标。
- 完整双镜像与 Harbor 自验要求主机能构建、启动 Docker。官方教程明确普通 AutoDL 容器实例无法完成此步；租用前核对所选实例实际能力。能运行算法或公开 Dev 不代表完成 Harbor 验证。

依据：项目内《AutoResearch 三期培训流程说明》的“如果需要 GPU”“第四步”；《AutoResearch 专家线下标注教程V3》的 Docker 说明与通用资源边界。执行时从项目文档目录定位这些资料，并核对任务卡的新版本。

## 按预跑结果选规格

|任务需求|候选资源|必须先验证|
|---|---|---|
|CPU 算法，无 GPU 需求|CPU 主机|内存、CPU 性能、公开与正式评分耗时、Docker 能力|
|单卡可容纳的训练或推理|优先评估 L20|真实显存峰值、单轮耗时、吞吐、依赖兼容性|
|显存要求更大或 L20 无法满足预算|评估 H20|实际型号与显存配置，是否解决容量/吞吐瓶颈|
|确需多卡且实现支持并行|按实测申请多卡|扩展效率、通信、CPU/内存/存储配套与批准的上限|

不能只凭论文原配置照搬卡数。用可代表正式负载的数据、方法和预算预跑，记录峰值显存、墙钟耗时、CPU/内存/磁盘与 GPU 利用率；小样本 smoke 不足以确定正式租期。Baseline 和 Reference 的公平协议、两组同资源要求仍需满足。

## 估算每个实例占用多久

把每个实例从开始计费到释放的连续时段列清：环境准备、数据与模型准备、预跑、全部正式 Baseline/Reference seed、Agent 迭代、模型重载与复评分、最佳方法干净复验、最终 NOP/质检、打包或返工期间仍占用的时间。模型 API 费用、存储/流量等费用单独列出。

**实例占用时长与 Agent 有效迭代时长不同。** Agent 的装包、下载、空等和只做形式化检查等不能自动计入有效研究时间，实例仍可能持续计费。两组各 10h 不意味着整题只租 20h；B/R、准备、验证和余量也需要安排。GPU 小时表示预留的卡数 × 占用时间，不证明实际 GPU 运算或 Agent 有效时长。

顺序运行两组时，将它们的实例占用计入同一时间线。用两个独立实例并行可缩短墙钟，但仍付两实例费用，且两组应隔离、同资源配置。若同规格的多个实例持续时长不同，分别计算；不能将小时合并后只做一次按天向上取整。

```text
计划每实例小时 = 余量前连续占用小时 × (1 + 余量百分比 / 100)
小时租总价 = 每实例小时价 × 计划每实例小时 × 实例数
日租每实例天数 = ceil(计划每实例小时 / 24)
日租总价 = 每实例日价 × 日租每实例天数 × 实例数
计划 GPU 小时 = 计划每实例小时 × 实例数 × 每实例卡数
```

如供应商按“每卡”报价，先转换为完整实例报价，再传给脚本；脚本不会额外乘卡数。CPU、内存等可能已有整机收费，按供应商合同转换，不能盲目把整机报价再乘 GPU 数。最低租期、按整小时取整、自然日计费、阶梯折扣等不符合上述模型时，按实际合同另外核算。

一个排期示例：准备与验证 4h、B/R 6h、两组各预留 11h，顺序占用共 32h；加 25% 时间余量后为 40h，按连续 24h 日租可申请每实例 2 天。这只是排期示例，未给出供应商价格，也不能替代任务预跑与有效时长证据。

## 离线预算工具

在 Skill 根目录运行 `scripts/gpu_budget.py`。仅使用 Python 标准库，成功时 stdout 输出 JSON；非法参数向 stderr 报错并非零退出。报价必须通过互斥的 `--hourly-price` 或 `--daily-price` 提供，另必填 `--hours-per-instance`。

|参数|含义|
|---|---|
|`--hourly-price` / `--daily-price`|每实例每小时 / 每连续 24h 的价格，二选一；有限且 ≥0|
|`--hours-per-instance`|每实例加余量前的连续占用小时，有限且 >0|
|`--instances`|同规格、同持续时长的实例数，正整数，默认 1|
|`--gpus-per-instance`|每实例卡数，非负整数，默认 1；CPU 实例填 0；只影响 GPU 小时|
|`--buffer-percent`|增加的时间百分比，有限且 ≥0，默认 0|
|`--quote-source`|实际报价来源的文本备注；不会在线核实|
|`--quote-date`|实际报价日期，格式 `YYYY-MM-DD`；不自动填今天|

以下价格 **仅为检验计算的虚构数值**：

```powershell
# 连续 32h，加 25% 后 40h；每实例日租 2 天
python scripts/gpu_budget.py --daily-price 100 --hours-per-instance 32 --buffer-percent 25 --quote-source "假设报价，仅测试计算"

# 两个实例，每实例四卡；每实例报价只乘实例数
python scripts/gpu_budget.py --hourly-price 10 --hours-per-instance 1.5 --instances 2 --gpus-per-instance 4

# 使用实际报价时，记录真实来源与报价日期
python scripts/gpu_budget.py --hourly-price <实际整机小时价> --hours-per-instance <预跑和排期小时> --quote-source "<供应商/订单/报价链接>" --quote-date <实际报价日期>
```

第一例结果为 `planned_hours_per_instance="40"`、`billable_days_per_instance=2`、`billable_hours_per_instance="48"`、`total_cost="200"`。第二例结果为计划实例小时 `"3"`、计划 GPU 小时 `"12"`、总价 `"30"`，不会因四卡再次乘价。

输出的小时、单价和金额使用十进制字符串，保留精确计算值；`total_cost_rounded_2dp` 是总价按四舍五入保留两位后的展示值。实际货币与输入报价相同，无汇率换算。日租同时输出计划与计费小时/GPU 小时，便于识别取整产生的闲置预算；按小时计费的 `billable_days_per_instance` 为 `null`。输出是预算估计，不能作为已审批、已付款或实际运行证据。

## 资源申请与复核

将实测规格、排期、每实例报价/币种/计费规则、来源日期、数量、申请天数、租赁总价及其他费用填入资源申请。异构规格或持续时长不同的实例分别调用脚本，再汇总成本；脚本的金额未包含 API、存储、流量等额外费用。按项目流程获批后使用，保留实际开始/释放时间及订单，租期或规格变更按项目要求复核。
