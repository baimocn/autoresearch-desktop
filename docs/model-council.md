# 模型议会（独立工作台）

`packages/dsh-model-council` —— 一个**独立**的侧边栏面板：多个模型按固定身份
**对抗审议**一个方向，最后由裁决者定夺。

它与 AutoResearch 工作台（`dsh-autoresearch-ui`）**不共用任何东西**：独立面板键
（`council`）、独立路由前缀（`/api/model-council`）、独立配置文件。它不读任务
目录，也不参与任何门禁 —— 是决策辅助工具，不是流程的一环。

## 身份分层

| 身份 | 举证义务 | 明确禁止 |
|---|---|---|
| **议员** councilor | 给出一个明确主张：判断、依据、预期收益，以及最可能失败的地方 | 不许罗列多个方案让裁决者挑 |
| **对抗者** adversary | 必须找出 ≥3 个具体失败模式 / 反例 / 未验证假设，逐条编号 | 找不到就写「我找不到」；不得编造凑数 |
| **裁决者** adjudicator | 通读全部发言后裁定：结论 / 理由 / 执行条件与不可逆性 / **推翻条件** | 不得取多数意见，不得和稀泥 |

构成约束：**裁决者恰好 1 位，议员 ≥1，对抗者 ≥1**，总数 3–8。缺对抗者的议会
只是并行自说自话，暴露不了偏差；多个裁决者会给出互相矛盾的裁定。

## 为什么不是「多模型讨论」

让几个模型各写一版再取共识，分歧会被**平均掉**而不是被**解决**。三个模型若共享
同一批训练偏差，它们会一起错，而「多数一致」会让这个错误显得更可信 —— 风险
反而**升高**。所以产出不是「一个更对的答案」，而是「一个方案 + 已知的反驳 +
明确的代价 + 一个能被推翻的裁定」。

这与 `docs/deliberation-board.md`（工具形态的审议台）是同一条设计原则的两种
落地：那边是对话里调用的一次性工具，这边是有配置页与会话历史的独立面板。

## 每路独立配置

每位成员独立设置 **地址（baseURL）/ 协议 / 模型 / 密钥**，不引用全局 provider 表。
模型 id 不靠手打：点「探测」拉取该端点的模型列表再选。

支持的协议（与 pi-ai 一致）：`openai-completions` / `openai-responses` /
`anthropic-messages`。baseURL 是否带 `/v1` 各家不统一，所以每个协议给出候选
路径，按顺序试到第一个非 404 —— 不需要用户纠结。

密钥写进 `$DSH_HOME/.credentials.yaml` 的 refs 段（引用名 `COUNCIL_<ID>_API_KEY`），
议会配置文件里**只有引用名**；页面只显示「有值 / 无值」，不回显密钥本体。

## 接入正在跑的普通会话（议会模式）

议会不只是一个面板。用命令把它接入**正在跑的普通会话**后，它就**替代人工**
在决策点上做选择 —— 这是无人监管模式。

| 命令 | 作用 |
|---|---|
| `/council` | 建议式：注入纪律 + 提供工具 |
| `/council-strict` | 强制式：另加「高风险工具须先取得裁定」+「禁止询问用户」 |
| `/council-off` | 退出 |

三个命令都**不声明 input**：声明了 input 的命令第一次 Enter 只认领参数、不执行，
最常用的无参路径被迫按两次回车（autoresearch 实测用户视为「没反应」）。
参数化形态因此拆成独立命令，而不是 `/council strict`。

### 无人监管的语义

模式激活后，系统提示里多一段 `<model_council>` 纪律：当对话走到**需要人工决策**
的点（在多个方案间选择、不可逆动作前取舍、本来要调用 `ask_user_question`），
**不要停下来等用户**，改为调用 `council_convene`，把「本轮上下文 + 候选选项」
交给议会，把返回的 `chosen` 当作用户的选择继续执行。

### 两个工具

| 工具 | 作用 |
|---|---|
| `council_convene` | 召开议会：`{question, context, options[], rounds?, waitMs?}`。跑 `rounds` 轮 + 裁决，最多等 `waitMs`（默认 300s，上限 900s）；超时返回 `running` 与会话 id，由模型用 `council_read` 续等 |
| `council_read` | 读取一场议会：状态 / 当前发言人 / 完整议事记录 / 裁定。既是轮询手段也是留痕 |

两个工具在**模式未开启时直接拒绝**并告诉调用方该执行哪条命令 —— 命令是真的开关，
不是装饰。已配置成员 <3 位时也拒绝，并指向配置页。

### 选项裁定

`options` 非空即进入**选项裁定**形态：议员必须支持其中一个（不许中立罗列），
对抗者必须指出「若选某选项会怎样失败」≥3 条且覆盖不止一个选项，裁决者必须
**选定恰好一个**并以 `选定：<选项原文>` 为首行。解析不出就 `chosen: null` ——
绝不猜；一个假的 `chosen` 会让无人监管的会话基于错误的选择继续往下走。

### 强制式拦什么

`bash` / `pwsh` / `write` / `edit` / `str_replace_editor` —— 判据是**不可逆**。
只读工具一律不拦（拦只读除了烦人没有安全收益）。`ask_user_question` 不在限制
清单里：它由 guard **重定向**到议会（拒绝只会让模型换个说法再问，重定向才真的
替代了人工）。拿到一次裁定后高风险工具自动放行，但重定向保留。

### 状态与持久化

模式状态折叠自 `command/run` + `command/done`（harness 已知事件类型）。**不用
自定义事件类型**：会话读取路径拒绝解释含未知类型的日志，而 `Session.append()`
无法设置 `ignorable` 信封标记（插件够不到）—— 仓库实测踩过，自定义事件会导致
整个会话历史加载失败。

政策章节按会话求值（`section.text(context)` 能拿到 `context.agent`，
`dsh-plan-mode` 同做法）。这比 `dsh-autoresearch` 的进程级全局标志干净：
多会话并行时全局标志本来就会串味。已顺带更正那两处「无法按会话求值」的旧注释。

### 刻意不接门禁

议会不参与 `advance`，也不改变任何门禁判定。把它变成硬门禁会让它退化成合规
仪式（见 `docs/deliberation-board.md`）。强制式拦的是**工具**，不是流程判定。

## 议事流程

1. 「议会配置」页配好成员并保存。
2. 「议事厅」新建会话，填议题。
3. **开一轮**：议员依次陈述（后发言者看得到先发言者），对抗者依次攻击。
4. **请裁决者裁定**：裁决者通读议事记录后给出裁定（含推翻条件）。
5. 主持人可随时插入发言影响后续发言者；可反复开轮与重裁。

## 文件

```
$DSH_HOME/model-council.json                参与者名单（含各路 URL/协议/模型）
$DSH_HOME/.credentials.yaml                 各路密钥（refs 段）
$DSH_HOME/model-council-sessions/<id>.json  会话与完整议事记录
```

## 长任务与失败处理

一轮议事 = 成员数 × 单次模型延迟，所以「开一轮」只负责**启动**，页面轮询进度。
进程重启后历史仍在，但不会假装那次运行还在继续（重启即中断，如实标为 idle）。
某一路鉴权失败或超时，会在议事记录里留一条明确的错误条目 —— 不静默跳过，
否则裁决者会基于残缺信息定夺。

| `client.js` | 浏览器面板（议事厅 + 议会配置），成员陈述走 `MarkdownText` |

验证：
- `node scripts/ablation-council.mjs` —— 110 项。含**桩化 fetch 的端到端编排**
  （开一轮 → 议事记录按身份顺序 → 失败路被如实记录 → 裁定条目落盘 →
  选项裁定把 `chosen` 落盘）、**配置写入往返**、**模式折叠与政策章节**、
  **选项提示词与 `chosen` 解析**、**工具的模式门控与命令面**。
- `node scripts/verify-integration.mjs` —— 真实进程下验证插件激活、客户端
  bundle 进入启动图、五条路由可达、apply 跑到底（模式与工具均已注册）。
- `node scripts/tool-registry-guard.mjs` —— 断言两个工具真的注册进 `ctx.tools`。
- `node scripts/devtools/cdp-verify-council.mjs` —— 浏览器内验证导航行出现、
  面板挂载、两页切换、**成员陈述真的渲染出 `<strong>`/`<table>`**、无未捕获异常。
  只读用户的议会配置与会话（临时会话用完删掉）。

**未验证项（如实声明）**：真实模型在三种身份下的**输出质量差异**未测 —— 需要
真实 API 调用且不可复现。消融只证明提示词与编排携带了身份义务，**不证明模型
会遵守它**。若模型无视身份约束、三路输出高度相似，本工具的价值就退回到
「同一模型的多次采样」。

## 顺带修掉的既有缺陷

扩展 `scripts/check-ui-tokens.mjs` 覆盖**所有** `packages/*/client.js` 后，发现
`dsh-ars-brand/client.js` 引用了两个不存在的 token（`--dsw-alias-bg-elevated`、
`--dsw-alias-border-secondary`）。写错的 token 名不会报错，只会静默回退 ——
这正是该脚本存在的理由。已改为真实存在的 `--dsw-alias-bg-layer-2` 与
`--dsw-alias-border-l2`。
