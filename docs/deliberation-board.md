# 决议审议台

多模型对抗审议一个方向，用于降低单模型偏差带来的决策风险。

## 第一性原理：为什么不做「多模型讨论」

「让几个模型讨论出一个方案」有个隐藏陷阱。如果实现方式是各写一版再取共识，
分歧会被**平均掉**，而不是被**解决**。三个模型若共享同一批训练偏差，它们会
一起错；更糟的是「多数一致」会让这个错误显得更可信。所以朴素的多模型讨论
不但不能降低风险，还可能**升高**风险。

真正降低风险的结构是**对抗**，不是投票。所以这里的每一路有固定的举证义务，
彼此不重复：

| 角色 | 举证义务 | 明确禁止 |
|---|---|---|
| **提案方** propose | 给出一个明确方向，说明依据、预期收益、以及自己认为可能失败的地方 | 不许罗列多个方向让决策者挑。选一个，并为它负责 |
| **反例方** counter | 必须找出至少 3 个具体的失败模式、反例或未验证假设 | 找不到就写「我找不到」。不得为凑数编造，不得复述提案方的话 |
| **代价方** cost | 给出资源、时间、许可代价，并判断不可逆性 | 不评价方向好不好。只算代价，让决策者自己权衡 |

产出不是「一个更对的答案」，而是「一个方案 + 已知的反驳 + 明确的代价」。
让决策者看到风险边界，而不是被一个自信的答案安抚。

反例方是**强制项**。配置里没有反例方会被直接拒绝 —— 没有反例的审议只是
几个模型并行的自说自话，暴露不了任何偏差。

## 为什么不接门禁（这条是刻意的）

一旦审议结论成为 `advance` 的前置条件，它就会退化成合规仪式：使用者会为了
过门而凑一份「看起来被审议过」的记录，而不是真的用它做决策。

所以本模块只产出材料，不产出判定，也不被任何门禁读取。聚合器**刻意不做**
裁判、不打分、不投票，只做三件事：按角色归类结论、标出失败的路、标出角色缺席。

审议结论里带一条固定的免责声明，写明它不能替代实测证据、也不等于
`G-FEASIBILITY` 通过。审议说「可行」和实测 `R_norm ∈ [0.15, 0.8]` 是两件事。

## 独立性如实分级

不假装多路就是独立。同 provider 同 model 的多路只是**同一模型的多次采样**，
能减少随机性，不能减少系统性偏差。

| 判定 | 条件 | 说明 |
|---|---|---|
| `single` | 所有路 route+model 相同 | 只能减少随机性，不能减少系统性偏差 |
| `same-provider` | route 相同，model 不同 | 偏差部分相关，独立性中等 |
| `multi-provider` | route 不同 | 独立性最高 |

分级结果写在 manifest 里，使用者能看到自己这次拿到的是哪一档，而不是被
「多模型审议」这个说法安抚。

## 用法

```
autoresearch_deliberate({
  question: '是否应该把上游资产改为自动同步？',
  context: '可选背景材料；角色不会复述它',
  lanes: [
    { route: 'llapi-a', model: 'deepseek-v4.1-flash', role: 'propose' },
    { route: 'llapi-b', model: 'deepseek-v4.1-flash', role: 'counter' },
    { route: 'llapi-a', model: 'deepseek-v4.1-flash', role: 'cost' },
  ],
})
```

2 到 6 路。上限存在的理由：路数越多，每个角色的举证义务被稀释得越厉害，
最后退化成每路都说一点什么都不说透。

路由与模型可先在工作台「双路质检」页或 API 配置页配好，工具会自动补全
`api`、`baseURL`、密钥引用。缺凭据的路会**如实报出**，不会静默少跑一路。

留痕目录结构：

```
<outDir>/
  lane-1/deliberation.txt      提案方原始输出
  lane-2/deliberation.txt      反例方原始输出
  lane-3/deliberation.txt      代价方原始输出
  lane-N/stderr.log            失败时保留
  deliberation-manifest.json   身份、独立性分级、退出码、角色归类
```

## 与双路质检的关系

两者共用隔离基建（独立 `DSH_HOME`、独立凭据注入、独立进程、原始输出落盘），
但**结论语义完全不同**：

| | 双路质检 | 决议审议台 |
|---|---|---|
| 对象 | 已经做完的题 | 还没成形的方向 |
| 结论 | `PASS` / `NOT_READY` / `INCOMPLETE` | 不判定对错，只暴露分歧 |
| 是否接门禁 | 是（发布门要求） | **否**（刻意） |
| 身份要求 | 两路两两不同，相同则拒绝启动 | 允许相同，但如实标注独立性等级 |

## 消融实验验证

`node scripts/ablation-deliberation.mjs` 共 26 项，全部通过。验的是
**提示词是否真的携带角色义务**，而不是「模型是否遵守」：

- 反例方是强制项（缺席即拒绝）
- 三种角色的提示词**互不相同**（不是同一段话换标签）
- 反例方的义务含**可数的**失败模式数量要求（「请找出问题」是无效指令）
- 反例方被明确禁止编造
- 提示词禁止模型模拟其他角色（否则会写出掩盖真实分歧的假审议）
- 独立性分级如实（3 档，同一模型不冒充独立）
- 聚合器含免责声明且不含 `PASS`/`FAIL` 字段
- 角色失败或缺席被如实报告，`exitCode` 原样保留
- 路数上下限生效

### 未验证项（如实声明）

**真实模型在三种角色下的输出质量差异未测。** 需要真实 API 调用，且结果
不可复现。本实验只证明提示词携带了角色义务，**不证明模型会遵守它**。

这条限制是实质性的：如果模型无视角色约束、三路输出高度相似，那么本模块
提供的价值就退回到「同一模型的多次采样」，即 `single` 档。要验证这一点，
需要在有凭据的环境跑一次真实审议，人工比对三路输出的差异度。这一步
尚未做。
