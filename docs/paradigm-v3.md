## 0. 结论

| 范式要求（原文） | 平台强制机制 |
|---|---|
| 「六道闸门必须依次通过，不许合并、不许跳」 | 闸门 manifest 落盘：闸门 N 调用先查 N−1 确认记录，缺哪个点哪个（实测：直接跑闸门 3 → 「闸门 1、2 尚未确认」拒绝） |
| 「每通过一道停下等使用者确认」 | 问题清单非空时 `confirm` 不生效；确认写入 manifest 才解锁下一道 |
| 闸门 1「18 份参考规范逐一列名」 | 扫描内置 0.3.10 skill 的 references/，缺一份或数量 ≠18 即点名 |
| 闸门 2「先出空表，status 全部留空」 | 生成 30 行骨架（21 QA + 6 H + 3 G） |
| 闸门 3「没 evidence 不许 pass」 | evidence 空/无行号且 status=pass → 点名「最高 manual」；manual+空 evidence 是合法组合（实测修正过一次误报） |
| 「不许出现『看起来没问题』类表述」 | 禁语表逐项扫判定依据 |
| 闸门 4.10「判读队列每条必须落锤，只允许四种处置」 | 处置词封闭集（确认正确/确认无关/确认错误/无法判定），第五种写法（明显无关/其他）直接拒收；确认无关须给逐字特征；条目数 ≠ 落锤数即未完成 |
| 闸门 4.8「归属判定只允许一致/误植/无法确认；误植 → QA21 fail」 | 逐条校验判定词与实现证据定位 |

## 2. 诚实边界

- **语义深度仍在审阅者。** 平台强制的是「每张表都在、每项都判了、处置词
  都合法、闸门没跳」——不能强制「判得对」。「判得对」靠两路互证 + 核验卡
  的人工追问。
- **否定结论分母是启发式**：同句无数字记 advisory 不阻塞——分母是否真实
  只有质检方自己知道，机制只能把它摆到眼前。
- **闸门 4 的深挖表内容不做语义校验**（绕过面表是否有三路径推演文字、
  归属核对是否真的逐条对应）——这些的机检边界与红线 1 相同：结构可保证，
  判断不可替代。
